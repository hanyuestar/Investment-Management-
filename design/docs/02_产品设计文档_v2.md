## 0. 一句话定义

一个**以"真实收益"为核心**、**可 Docker 自部署**的个人投资账本：支持理财 / 债券 / 股票 / 基金四类资产、人民币与美元双币种，**按每笔交易发生时的汇率锁定成本**，自动算出股票摊薄成本（含做 T、分红、送股、拆分）、已实现/浮动盈亏，并按月、按年汇总投资收益。数据存服务器，SQLite 持久化，支持 JSON 导入导出。

## 2. 核心设计难点与方案

### 2.1 行情/汇率"动态性"处理原则（基石）

用户明确要求：**"汇率只对记录时的金额生效，调整后的汇率只对后续变化的投资金额生效"**。

- **做法**：每条交易/现金流记录保存时，把**当时的汇率（CNY per 1 USD）固化写入记录自身**（`fx` 字段）。
- 汇率管理维护一条"汇率历史时间线"，仅用于：① 新增记录时自动带出默认值（可手动覆盖）；② 审计追溯；③ 计算**当前市值**时使用"最新汇率"。
- **结果**：任一历史记录的资产成本永不被后续汇率变动改写 → 得到"真实的本币收益"。
- **规则**：人民币资产汇率恒为 `1`（录入时锁定，不可改）。

> 示例：1 月以 7.10 买入 1000 美元资产（成本 ¥7100）；6 月汇率调到 7.28，此前成本仍为 ¥7100，不被重估。仅在估值/卖出时用当天汇率算市值与浮盈。

### 2.2 股票成本算法（含做 T）

采用**移动加权平均法（摊薄成本）**，符合 A 股散户"做 T 降成本"直觉。逐笔按时间顺序处理：

| 事件 | 处理规则 |
|---|---|
| **买入** | `qty += 买量`；`成本总额 += 买量×价 + 手续费` |
| **卖出** | `单位成本 = 卖出前成本总额 ÷ 卖出前股数`；`已实现 += (卖额−手续费) − 单位成本×卖量`；`成本总额 −= 单位成本×卖量`；`qty −= 卖量` |
| **现金分红** | `已实现 += 分红额`；**不改股数与成本**（除权后若成本需下调，可选用"分红冲减成本"模式，见待确认项） |
| **送股/转股** | `qty += 送股数`；**成本总额不变** → 摊薄成本自动下降 |
| **拆分/合股** | `qty ×= 比例`；**成本总额不变**（0.5 即合股） |
| **做 T** | 无需特殊处理，按时间顺序逐笔结算，净效果=摊薄成本随价差增减 |

**双口径展示**（解决"实际成本价"歧义）：

| 口径 | 含义 | 用途 |
|---|---|---|
| **摊薄成本价**（主） | 移动加权平均，受卖出/T/送股影响 | 判断盈亏、决定是否继续持有 |
| **累计买入均价**（辅） | 累计买入金额 ÷ 累计买入股数 | 参考"原始买入成本" |
| **成本价（原币/本币）** | 分别以资产币种、人民币计 | 美元资产看真实人民币成本 |

### 2.3 双币种换算

- 基准货币 = **人民币 CNY**，所有汇总以 CNY 呈现；每笔记录带 `currency` + `fx`。
- `投入本金(¥) = Σ 投入额 × 该笔fx`；`已实现(¥) = Σ 卖出/收入额 × 该笔fx − 对应成本(¥)`
- `当前市值(¥) = 市值(原币) × 最新汇率`；`浮动盈亏(¥) = 市值(¥) − 剩余成本(¥)`
- 股票剩余成本(¥) 随买卖按比例结转，保证"历史汇率锁定"贯穿整条成本链。

### 2.4 月度 / 年度收益（两种口径）

1. **已实现收益（现金流口径，精确）**：股票=当月卖出实盈 + 现金分红；理财/债/基金=当月分红利息。
2. **含浮动总收益（快照口径，可选）**：需用户记录"月末总资产快照"。
   `月度含浮动 = 当月已实现 +（本月末总资产 − 上月末总资产 − 当月净投入）`
   无快照则留空标"未记快照"。不依赖行情接口，数据准确性由用户掌控。

### 4.3 表单字段明细

**A. 新增资产（AssetForm）**：名称\*、代码（选填）、类型\*（股票/基金/理财/债券）、币种\*（CNY/USD）、现价或当前市值。**类型与币种创建后不可改**（避免成本链错乱）。

**B. 交易录入（TradeForm）— 按类型动态切换**

| 类型 | 字段 |
|---|---|
| 买入 / 卖出 | 日期\*、数量\*、成交价\*、手续费、汇率\*（锁定）、☑标记为做 T、备注 |
| 现金分红 | 日期\*、分红总额\*、汇率\*、备注 |
| 送股 / 转股 | 日期\*、送股数量\*、汇率\*、备注 |
| 拆分 / 合股 | 日期\*、拆分比例（1 股→N 股）\*、汇率\*、备注 |

**C. 现金流（FlowForm，理财/债券/基金）**：日期\*、类型\*（投入/赎回/分红利息）、金额\*、手续费、汇率\*、备注。

**D. 汇率（FxForm）**：生效日期\*、1 USD = ? CNY\*、备注。保存后**仅作为后续新记录默认值**，不回改历史。

### 4.4 校验与交互规则

- 卖出数量 > 持仓 → 高亮警示（允许，支持补录历史）。
- 汇率 > 0；金额/数量/比例 > 0；日期可补录（提示但允许）。
- 新记录保存后：Toast + 相关 KPI/看板数字高亮闪烁。
- 删除均需二次确认；人民币记录汇率框置灰锁定为 1。
- 首次访问若检测到 `localStorage` 不可用（如 `file://`）自动回退内存模式，不打断演示。

## 5. 核心计算逻辑（伪代码）

```text
currentFx() = 最近一条 日期<=今天 的 fx.rate
assetFx(a)  = a.currency==='USD' ? currentFx() : 1        # 人民币恒为 1

# 股票
for t in trades(asset).sort(byDate):
  if t.side=='buy':   qty+=t.qty; costLocal+=t.qty*t.price+t.fee; costCNY+=(...+fee)*t.fx
  if t.side=='sell':  avgL=costLocal/qty; avgC=costCNY/qty
                      realCNY += (t.qty*t.price-t.fee)*t.fx - avgC*t.qty
                      costLocal-=avgL*t.qty; costCNY-=avgC*t.qty; qty-=t.qty
  if t.side=='div':   realCNY += t.amount*t.fx            # 只增已实现
  if t.side=='bonus': qty += t.qty                        # 成本不变→摊薄降
  if t.side=='split': qty *= t.ratio                      # 成本不变

摊薄成本价(¥) = qty>0 ? costCNY/qty : 0
市值(¥)       = qty * latestPrice * assetFx(a)
浮动盈亏(¥)   = 市值(¥) - costCNY
总盈亏(¥)     = 已实现(卖出+分红) + 浮动
收益率        = 总盈亏 / 累计买入金额(¥)

# 现金流型（理财/债券/基金）
投入/收回/收入(¥) = Σ 对应金额 * fx
市值(¥) = 当前市值 * assetFx(a)
总收益(¥) = 收回 + 收入 + 市值 - 投入

# 月度/年度
月度已实现(¥) = Σ 股票当月(卖出实盈+现金分红) + Σ 现金流当月分红利息
月度含浮动(¥) = 月度已实现 + (本月末快照 - 上月末快照 - 当月净投入)
年度 = Σ 该年各月
```

## 6. 部署与持久化架构（v2 新增，按用户要求）

**目标**：Docker 自部署，数据存服务器，SQLite 持久化，支持 JSON 导出/读取。

### 6.1 技术选型（建议）

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | Vue3 / React 单页（沿用原型逻辑） | 原型 HTML/JS 可直接迁移 |
| 后端 | Node.js(Express/Fastify) 或 Python(FastAPI) | 轻量、易打包 |

| 部署 | **Docker + docker-compose** | 一键起，数据卷持久化 |
| 备份 | **JSON 导出/导入 API** + 卷快照 | 需求 3 明确要求 |

### 6.3 数据库表结构（SQLite）

```sql
-- 汇率时间线（仅影响"日期之后"的新记录）
CREATE TABLE fx_rate (
  id INTEGER PRIMARY KEY, date TEXT NOT NULL, rate REAL NOT NULL,
  note TEXT, created_at TEXT
);

-- 资产（一只股票/基金/理财/债券）
CREATE TABLE asset (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, code TEXT,
  type TEXT NOT NULL CHECK(type IN ('stock','fund','wealth','bond')),
  currency TEXT NOT NULL CHECK(currency IN ('CNY','USD')),
  price REAL,               -- 股票最新价
  market_value REAL,        -- 现金流型资产当前市值（原币）
  sort INTEGER, created_at TEXT
);

-- 交易/现金流统一事件表（type 区分）
CREATE TABLE event (
  id TEXT PRIMARY KEY, asset_id TEXT NOT NULL REFERENCES asset(id) ON DELETE CASCADE,
  date TEXT NOT NULL,
  kind TEXT NOT NULL,       -- stock: buy/sell/div/bonus/split; flow: invest/redeem/income
  qty REAL,                 -- 买/卖/送股 数量
  price REAL,               -- 成交价
  amount REAL,              -- 分红/现金流金额
  ratio REAL,               -- 拆分比例
  fee REAL DEFAULT 0,
  fx REAL NOT NULL,         -- ★ 记录时锁定汇率
  is_t INTEGER DEFAULT 0,   -- 是否做 T（仅统计）
  note TEXT, created_at TEXT
);

-- 月末总资产快照（含浮动收益用）
CREATE TABLE snapshot (
  month TEXT PRIMARY KEY, total REAL NOT NULL, created_at TEXT
);
CREATE INDEX idx_event_asset_date ON event(asset_id, date);
```

> **不存储任何"已计算"的派生结果**（成本、盈亏一律运行时由 `event` 实时算出），避免数据不一致；仅在需要性能时加缓存表。

### 6.4 后端 API（REST）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/state` | 返回全部数据（asset/event/fx/snapshot），前端一次性拉取 |
| POST | `/api/assets` · PATCH/DELETE `/api/assets/:id` | 资产增改删 |
| POST | `/api/assets/:id/events` · DELETE `/api/events/:id` | 交易/现金流增删 |
| GET/POST | `/api/fx` · DELETE `/api/fx/:date` | 汇率时间线 |
| GET/POST/DELETE | `/api/snapshots` | 月末快照 |
| **GET** | **`/api/export`** | 导出完整 JSON（含版本号） |
| **POST** | **`/api/import`** | 导入 JSON（校验 + 事务覆盖） |
| GET | `/api/summary` · `/api/reports/monthly` · `/api/reports/yearly` | 服务端算汇总（可选，也可前端算） |

**JSON 导出格式**（与原型 `localStorage` 结构一致，便于互通）：
```json
{ "schema":"invest-manager/v2", "exportedAt":"2026-09-22T...",
  "fx":[...], "assets":[...], "snapshots":[...] }
```
导入策略：事务内 `DELETE` 全部 → 批量 `INSERT`；导入前自动落一份 `data/backups/auto_YYYYMMDD_HHmm.json`。

### 6.5 计算位置

- **推荐**：后端只做 CRUD + 存储；**计算放前端**（原型算法可直接搬），减少接口、响应快。若未来要出服务端定时报表，再把计算函数抽成共享模块（Node 可直接复用 JS 版本）。

## 8. 待确认的设计取舍（需与潘先生讨论）

1. **成本口径**：默认摊薄加权平均；是否需要额外提供 **FIFO 先进先出**可选？
2. **现金分红处理**：默认"计入已实现收益、不减成本"；是否提供 **"分红冲减成本"** 模式（除权后成本下调）？两种派系都有用户，建议做成开关。
3. **前端框架**：Vue3 还是 React？（影响后续大模型开发提示词）
4. **后端语言**：Node.js 还是 Python(FastAPI)？
5. **鉴权**：单用户是否要登录（简单密码/token）？还是仅内网访问？
6. **股票最新价**：手动录入（v2 默认）还是接行情接口（腾讯/新浪）自动更新？美元资产是否也要自动汇率？
7. **多账户**：是否需要区分"多个券商/银行账户"？（当前设计为单一账本）
8. **税费**：卖出是否需要单独记录印花税/过户费（当前并入"手续费"一项）？

## 9. 后续移交开发（给大模型/开发者的提示）

- **数据模型**：见第 6.3 节 SQLite 表结构（`fx_rate` / `asset` / `event` / `snapshot`）。
- **可复用算法**：原型 `index.html` 内 `calcStock()` / `calcFlow()` / `monthRows()` / `yearRows()` / `currentFx()` / `assetFx()` 均为纯函数，可直接移植到前端或服务端共享模块。
- **开发顺序建议**：
  1. 数据模型 + SQLite 初始化/迁移
  2. 计算引擎（纯函数，先写单测）
  3. 资产 & 事件 CRUD API
  4. 前端：持仓看板 → 交易录入 → 总览 → 报表
  5. 汇率、快照、JSON 导入导出
  6. Docker 打包 + compose + 数据卷验证（重启容器数据不丢）
